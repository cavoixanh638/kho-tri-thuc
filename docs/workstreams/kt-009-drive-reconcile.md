# KT-009/106 · Đối soát Drive và kiểm chứng mapping

- Nhánh `codex/kt-009-drive-reconcile`, gốc `ea315f7c3e6559ff79725665022e8ad86abcaa64`, code đã thử `da0c126f8e592064ed8f46ff7f4ac2301fb8c9d6`.
- PostgreSQL 18.4 tạm trên Windows, 27/27 test backend PASS gồm 8 ca KT-009/106 với Drive giả. Kiểm tra migration, Ruff format và lint E4/E7/E9/F/I đều qua. Không có migration mới.
- `probe_location(location, client=..., account=...)` đọc metadata dưới tài khoản chủ sở hữu và kiểm hai `appProperties` định danh Item/Asset. `reconcile_location` áp dụng kết quả nếu mapping chưa đổi sau lần đọc Drive. Kết quả trả trạng thái, mã lý do, tên hiện tại, revision và dấu hiệu parent trực tiếp khác root.
- `reconcile_drive --owner-id ID --limit 25 [--after-location ID]` kiểm mapping sau restore ở chế độ chỉ đọc. Thêm `--apply` để cập nhật cục bộ. Chạy từng batch theo cursor `next_after_location`. Lệnh không sửa file trên Drive, dùng OAuth cấu hình hiện có và không ghi token/tên file ra stdout.
- 404 mơ hồ và 403 được đánh dấu `inaccessible`. Chỉ dùng `missing` khi Drive xác nhận `trashed` cho đúng mapping. Thay đổi nội dung giữ checksum gốc đã xác minh, đánh dấu location chưa xác minh, tăng phiên bản Asset một lần mỗi revision và chuyển bản trích xuất/quan hệ hiện hành sang stale. Lỗi quay vòng tạm thời giữ trạng thái. [Lỗi Drive](https://developers.google.com/workspace/drive/api/guides/handle-errors#404-errors) · [Thuộc tính tệp Drive](https://developers.google.com/workspace/drive/api/reference/rest/v3/files).
- Trạng thái PASS với test mô phỏng. Upload thật, restore lên host mới với OAuth client giữ nguyên và quyền với Client/Project khác chưa chạy. Khi có môi trường kiểm thử, dùng cùng credential đang cấu hình ở host mới và chạy probe với mapping đã restore. Ghi kết quả từng 403/404/invalid_grant. Nếu đổi Client hoặc Project, thử lại dưới cấu hình mới và ghi nhận file cần cấp quyền lại.
