# Issue #90 / P08-J9 — đo SQL và tìm kiếm ở 10.000 mục (22/11/2026)

## Căn cứ
Trong [Actions #45007532129](https://github.com/cavoixanh638/kho-tri-thuc/actions/runs/45007532129), J9 đã PASS tính toàn vẹn 10.000 Item + 1.000 Topic, song P95 danh sách (100 lần) đạt **1.424,848 ms** và P95 SearchService (10 lần) đạt **3.367,265 ms** trên runner CI dùng chung. Không đủ căn cứ kết luận nguyên nhân chậm hay coi đây là độ trễ production.

## Thực hiện trên nhánh QA độc lập
- `tools/smoke/p08_query_profile.py` chỉ chạy với `P08_J9_ISOLATED=YES`, `P08_J9_PROFILE=YES`, database đúng `kt_p08_scale`, owner `p08-j9-scale-fixture` và đã kiểm đủ 10.000 Item/1.000 Topic.
- Mỗi lần đo bọc `connection.execute_wrapper`, ghi wall-clock, tổng thời gian thực thi SQL, khoảng không bao gồm SQL execute (fetch/hydration/serialize/overhead), số query và nhóm bảng. Chỉ lưu SHA256 prefix của **mẫu truy vấn**, không lưu SQL text, params, dữ liệu người dùng hay URL.
- 3 trang GET thực sự qua Django authenticated Client tại offset 0/5000/9900, mỗi trang limit 100; 3 truy vấn SearchService nhãn `exact_first`, `exact_last`, `common`; kiểm owner isolation.
- Chạy `EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON)` trên câu SQL SELECT đáng chú ý trong **transaction READ ONLY** với statement timeout 7 giây; lưu chỉ node/index/tổng số block/thời gian/rows, không lưu câu SQL gốc. Kết quả sẽ giúp phân biệt scan bảng, sort/temp spill, time decode/summarize và I/O.
- Bước CI bổ sung nằm sau J9 trong **cùng runner** và volume PostgreSQL QA, timeout 3 phút và `continue-on-error`. JSON ghi trong artifact hiện có `tmp/p08-kt128/p08-query-profile.json`.
- **Không sửa runtime/SQL hoặc migration trước khi có plan**; không tự đặt mục tiêu p95 hoặc tuyên bố mức độ đáp ứng production. Không thêm runner, cron, tác vụ định kỳ, provider API, Drive hay Gemini.

## Cách đọc và xử lý
1. Mỗi báo cáo có `wall_ms`, `sql_execution_ms`, `non_sql_or_fetch_ms`, `queries`, nhóm bảng. `non_sql_or_fetch_ms = max(0, wall_ms - sum(sql_execution_ms))`; đây là phần chênh lệch đo, không phân tách được chính xác JSON serializer và ORM.
2. Plan chỉ có `MEASURED_ISOLATED_POSTGRES` nếu thực chạy EXPLAIN; `NOT_RUN` nếu quá thời hạn hoặc thiếu SELECT. Không nâng release gate do phần này không trực tiếp nghiệm thu J3/J6B.
3. Cần so với **nhiều lần đo** và hiệu năng ngoài CI trước khi kết luận sửa query/index; 3 search mẫu **không dùng** để tính P95 chính thức (nearest rank sẽ là max của 3).
4. Issue theo dõi: [#90](https://github.com/cavoixanh638/kho-tri-thuc/issues/90).
