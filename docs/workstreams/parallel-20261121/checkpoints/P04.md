## Semantics and boundaries

- **Unfiled** means no active folder primary home and no active `ItemTopic` membership; `parent_item` is a note hierarchy and does not count as folder placement.
- An Item may have an active home with a missing legacy membership: show it in its primary folder, but do not create, duplicate, or transfer any original media/source.
- An Item with multiple folder assignments remains one UUID; membership-only views are shortcuts to the same Item.
- An unfiled note with an active note parent stays visible in the virtual unfiled collection and marked as a shortcut because its canonical structural position is nested under another note.
- Counts exclude deleted/cross-owner Items and use distinct IDs; folders come first in the mixed explorer stream. Stable ordering is `sort_order,name,id` (folders) and `outline_order,id` (notes).
- Offset paging remains offset-based (not snapshot-consistent under simultaneous inserts/deletes). The stale-version guard protects edits, not immutable reads. Cursor-based keyset pagination and snapshot isolation are **INTEGRATION_REQUIRED / future architecture choice**; do not describe offsets as a database cursor.
- Archived folder child-orphan/legacy inconsistent membership remediation and concurrency stress require full PostgreSQL checks. No existing pinned membership is removed by these read-only fixes.
