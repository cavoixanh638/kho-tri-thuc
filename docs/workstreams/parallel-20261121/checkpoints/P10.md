## Findings / reproduction

1. **P10-F01 — parser false negatives after punctuation (FAIL):** `catalog/groups_api.py::_inline_item_links` accepts explicit `[Tên](#/muc/UUID)` only when immediately preceded by whitespace/line start (regex `(?<!\\S)`). Thus `Xem:[Tên](#/muc/UUID)` is ignored, although valid Markdown. Both outgoing and backlink discovery may silently omit the genuine link. Severity **MEDIUM**; conservative policy prevents false positives but loses valid input. Repro: `p10-parser-audit.py --strict` case `punctuation_adjacent_valid_markdown`.
2. **P10-F02 — adjacent explicit Markdown links omitted (FAIL):** `[A](#/muc/UUID_A)[B](#/muc/UUID_B)` returns empty set in the source function, despite two valid UUID links. The parser's remaining bracket check drops whole line when second candidate cannot match. Severity **MEDIUM**; repro `two_adjacent_valid_markdown_links`.
3. **P10-F03 — valid autocomplete trigger after closed inline code omitted (FAIL):** `WikiCompletion.ts::wikiQuery` returns `undefined` on `\`code\` rồi [[Bài`, because it treats any prior backtick on the same line as code. A user cannot invoke autocomplete in ordinary prose after inline code. Severity **LOW/MEDIUM**; repro `p10-wiki-audit.mjs` `ordinary_text_after_inline_code`.
4. **P10-F04 — unclosed fenced code treated as prose (FAIL):** opening `\`\`\`md`, then `\`\`\`not-closed`, then `[[Bài` yields a completion trigger even though the second fence line contains an invalid trailing info string and does not close a CommonMark fenced block. Severity **MEDIUM**; repro `nonclosing_fence_with_info`. This is a completion-context defect, not demonstrated stored-link creation/XSS.
5. **No confirmed owner-data disclosure** from source review: all navigation/link endpoints filter `owner=request.user` and nondeleted rows; cross-user and deletion endpoint-level evidence remains NOT_RUN until Django tests execute.
